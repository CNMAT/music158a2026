## New v5 engine suite
**337,124 assertions passed.** The suite tests the exact supplied source, voice counts 1/4/12/20, constructor defaults and clamping, 12 independent scalar outlets plus a separate list outlet, known fixed-peak rise/fall/hold cycles, independent randomness, normalized finite outputs, idempotent start, stop/restart, deletion cancellation, parameter changes and the missed-boundary transition guard.

A simulated 120-second, twelve-voice run checked **92,220 output events**, including **6,002 summary lists**. This exercises the script through emulated Task/clock APIs; it does not measure real-time CPU performance.

## New integration suite
**3,630 assertions passed**, including **4,023 selectively emulated messages through the actual saved new control/readback graph**.

The checks verify scalar channel identity from v5 outlet through gate/clip/pack/line~ to the same-numbered existing routing multiplier. The thirteenth JS outlet reaches only the gain-target monitor. Original renderer/routing port order and every preexisting audio connection remain intact.

Startup is Bypass: closed gates prevent the original script's automatic load-start outputs from altering the gain layer; `line~ 1.` starts at unity; deferred initialization stops the generator. Stop and Bypass close the gates before stopping the source, then request 20 ms zero/unity transitions respectively. Auto interpolation follows the selected grain.

Local and external controls are checked together. External range changes normalize and update both visible fields and their silent `pak` cache. Editing one field therefore retains the other current value. Repeated Start preserves active cycles, Restart resets them, and unknown commands are reported instead of reaching arbitrary JS functions. The existing global lane Stop/All Off path stops active Auto but preserves Bypass.

Saved presentation rectangles are checked for bounds and new-versus-existing overlaps. This is geometry validation, not a rendering of the actual Max GUI. The help file's script references and saved ports are also checked.

## Routing / gain cautions
The new mixer acts on **spatial matrix outputs**, not directly on pre-matrix synthesis lanes. It multiplies the existing ADSRs; a silent envelope remains silent. Starting automation does not enable DSP or trigger an ADSR.

The twelve named group buses and mono FX sum are **post-automixer but pre-DAC-fader**. DAC master attenuation does not protect those named feeds. Keep appropriate receive-side gain control. Bypass restores unity in the added layer; it is not a mute.

The old and new v20 masters share v20 bus/store names. **Open only one v20 master/editor instance at a time.**
